## Releases
[GhostBSD 26.2-R15.1p6 Is Now Available](https://ghostbsd.org/node/68?utm_source=bsdweekly): GhostBSD 26.2-R15.1p6 is out, based on FreeBSD 15.1-RELEASE, with a new installer, full disk encryption via GELI, a smaller ISO, and fixes across tools like NetworkMgr, Update Station, and Backup Station.

## BSDSec

No security announcements.

As always, it's worth following [BSDSec](https://bsdsec.net). [RSS feed](https://bsdsec.net/articles.atom) available.

## News
[Enlightenment 0.28.0 Release](https://www.enlightenment.org/news/2026-10-31-enlightenment-0.28.0?utm_source=bsdweekly): Enlightenment 0.28.0 adds initial NetBSD support for power commands and signal handling, along with fixes for BSD battery module builds. The release also introduces a new NetworkManager module, native PipeWire mixer integration, an integrated clipboard history gadget, and battery charge limits.

[Valuable News - 2026/11/02](https://vermaden.wordpress.com/2026/11/02/valuable-news-2026-11-02/?utm_source=bsdweekly): This week's roundup highlights the release of GhostBSD 26.2, Omarchy ported to FreeBSD, setting up encrypted ZFS on NetBSD, progress on OpenBSD's GEFS filesystem, BSD Router Project 2.3, and AlpineBSD pairing the NetBSD kernel with Alpine Linux userspace.

[FOSDEM 2027 - Brussels, Belgium, 30 January 2027 - BSD, illumos, OpenZFS, bhyve Devroom Call for Presentations](https://bsdsec.net/articles/fosdem-2027-brussels-belgium-30-january-2027-bsd-illumos-openzfs-bhyve-devroom-call-for-presentations?utm_source=bsdweekly): Submissions are open for the BSD, illumos, OpenZFS, and bhyve devroom at FOSDEM 2027 in Brussels, with a presentation deadline of December 7, 2026.

[Work on GEFS for OpenBSD Progresses](https://www.undeadly.org/cgi?action=article;sid=20261101115637&utm_source=bsdweekly): Ori Bernstein shared an update on porting GEFS to OpenBSD, incorporating bugfixes from 9front, basic userspace utilities like mkfs, and a proposed design for handling filesystem consistency barriers.

[AI-Assisted Vulnerability Discovery Project: August and September 2026 Update](https://github.com/FreeBSDFoundation/all-projects/blob/main/AI-assisted-vulnerability-discovery/monthly-updates/2026-09.md?utm_source=bsdweekly): The FreeBSD Foundation reports that handling incoming vulnerability reports and producing advisories consumes most of the project's time, outlines LLM use cases for triage and code review, and notes progress on RTIR deployment, Forgejo setup, and non-LLM tooling like code sanitizers and fuzzing.

[Register Today for the Fall FreeBSD Vendor Summit](https://bsdsec.net/articles/register-today-for-the-fall-freebsd-vendor-summit?utm_source=bsdweekly): Registration is open for the Fall 2026 FreeBSD Vendor Summit, taking place November 5-6 at NetApp's campus in San Jose. The scheduled program features talks on cloud-native computing, NVIDIA DOCA support, discovering FreeBSD vulnerabilities with AI, and upstreaming experiences from NetApp.

[BSD Weekly - Issue 302](https://bsdweekly.com/issues/302?utm_source=bsdweekly): This issue covers FuguIta 8.0 test release, LibreSSL 4.4.0, OpenBSD errata for dbupdate, FreeBSD and NetBSD revoking compromised eMudhra CA certs, a Wine port for OpenBSD, OpenBSD 8.0 and LibreSSL 4.4.0 highlights, OpenBSD adding rtrd(8) and multi-processor VM support, and a ZFS configuration pitfalls guide.

## Tutorials
[ZFS: Diagnosing Database Bottlenecks: Storage, RAM, or CPU?](https://klarasystems.com/articles/diagnosing-zfs-database-bottlenecks/?utm_source=bsdweekly): A practical guide to pinpointing whether storage, RAM, or CPU is causing ZFS database latency, using latency histograms, ARC hit ratios, and worker-thread CPU time, with tuning steps ordered by cost and impact.

[Vim Alternatives on OpenBSD](https://www.tumfatig.net/2026/vim-alternatives-on-openbsd/?utm_source=bsdweekly): Evaluation of eight vi-compatible text editors on OpenBSD, including stock vi, nvi, vis, vile, elvis, and EVi, comparing features like UTF-8 support, syntax highlighting, split views, and spell checking.

[Run the Drill Again: Why DR Testing Needs a Shorter Cycle](https://klarasystems.com/articles/zfs-disaster-recovery-testing-shorter-cycle/?utm_source=bsdweekly): Klara Systems explains why ZFS disaster recovery testing should happen quarterly rather than annually, detailing silent failure points like missing encryption keys, feature flag drift, and broken snapshot chains. It outlines a step-by-step process using ZFS commands to verify replication lag, load keys, clone snapshots, and measure real restore times.

[Consolidating a Home Lab with Sylve](https://freebsdfoundation.org/our-work/journal/browser-based-edition/production-deployments/consolidating-a-home-lab-with-sylve/?utm_source=bsdweekly): Sven Rödiger explains how Sylve provides a browser-based UI to manage bhyve VMs, jails, and ZFS on FreeBSD without replacing base-system tools, letting him consolidate a sprawling home lab onto a few FreeBSD hosts while keeping existing Bastille jails and adding Linux and Windows workloads.
